# dsh-cold-hot-memory

给 [DeepSeek Harness](https://deepseek.com) 用的**冷热记忆插件**（实验版）。

目标：让长会话不必反复重启，也能持续记住"项目做到哪了、定了什么、还欠什么"。

> **状态：v0.1，实验阶段。** 引擎层有 18 项自测全部通过；插件与宿主的集成尚未在真实环境验证。请勿用于重要数据。

---

## 它解决什么问题

上下文窗口有限，聊得越久，早期的信息越容易被压缩掉。压缩是"有损"的——摘要一写，原文就看不见了。

这个插件不试图"不压缩"，而是把记忆分成三层，让该留的留住、该丢的丢掉：

| 层 | 内容 | 存多久 |
|---|---|---|
| **状态**（state） | 现在在做什么、卡在哪 | 每轮覆盖，只保留最新 |
| **结论**（decisions） | 定下来的事 + 为什么 | 长期保留，不可改写 |
| **未完成**（open） | 没做完的事 + 恢复卡 | 搁置 30 天后沉睡，90 天后归档 |

设计前提：**完成的事情大部分不会再被提起**，所以过程可以丢，结论必须留。

---

## 核心设计

### 1. 交付即完成，不等用户确认

大多数记忆系统都要人手动"标记完成"。实际用起来没人会这么干。

这里改成：**产物落地就标为已交付（`delivered`）**，用户有新要求时一句话重开。挂着不关的成本是持续噪音，重开的成本是一句话。

### 2. 结论不可变，方案原地改

- **结论**（`decisions/`）：要改就新建一条，旧的进 `archive/`。保留"当初为什么这么定"。
- **方案**（`designs/`）：原地修改同一个文件，变更记录写在文件内。避免文件夹爆炸。

### 3. 没人会说"不用管了"，所以用时间老化

```
delivered → 30 天无动静 → dormant（不注入）
dormant  → 90 天无动静 → archived（不在主索引）
```

任何一次提及都会让它立刻回到活跃。

### 4. 敏感信息在写入前拦截

支持中英文标签（`密码：`、`api_key=`、`token:` …），发现即拒绝写入。

### 5. 中文检索

- 分词用**双字滑窗**（bigram），而不是整段中文当一个词
- 检索用 **BM25** 排序，带层级、置信度、时间衰减
- token 估算区分 CJK / ASCII，不再用 `len/2` 低估中文

## 目录结构

```
lib/
├── engine.js   # 记忆引擎：分层存储、BM25 检索、去重、冲突检测、脱敏
└── index.js    # 插件入口：5 个工具 + 每轮注入
test.mjs        # 引擎自测（node test.mjs）
cordis.patch.yml
package.json
```

## 注册的工具

| 工具 | 作用 |
|---|---|
| `memory_write` | 写入一条记忆 |
| `memory_query` | 关键词检索（BM25） |
| `memory_stats` | 统计与预算告警，可触发保留期清理 |
| `memory_promote` | 在层级之间移动 |
| `memory_forget` | 归档（不删除，可检索） |

## 运行自测

```bash
node test.mjs
```

预期输出：`18 checks passed`。

## 安装（未验证）

插件以本地 bundle 形式装入 DSH profile：

```yaml
# cordis.patch.yml
- insert:
    - id: cold-hot-memory
      name: dsh-cold-hot-memory
```

安装后需要重启一次。**此步骤尚未在真实环境中验证**，`@deepseek-ai/dsh-tools` 等 peer 依赖的解析可能有问题。

## 已知限制

- 宿主集成未验证（工具注册、注入时序、peer 解析）
- 未做并发写保护（多会话同时写同一项目会冲突）
- 没有 UI
- 检索是纯关键词，无语义相似度
